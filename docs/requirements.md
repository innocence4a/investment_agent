## 1. プロダクトの定義

**「AI エージェントが自動売買している様子を、リアルタイムのダッシュボードで眺められるシステム」**

参照ポストから引き継ぐのは「見て面白いクオンツ風ダッシュボード」の体験であり、Polymarket や高頻度アービトラージ戦略そのものは複製しない。価値の中心は次の 2 つ:

1. **観察体験**: エージェントの判断(なぜ買った/売った/見送ったか)と成績がリアルタイムに流れるダッシュボード。デザインは参照画像より「見やすく・オシャレ」に(§6)
2. **実際に動く自動売買**: まずはペーパートレード(仮想売買)で本物の市場データを使って動かし、検証後に少額実弾へ

## 2. 対象市場: 仮想通貨を推奨(株式は代替案)

| 観点 | 仮想通貨(推奨) | 株式(国内) |
|------|----------------|--------------|
| 市場時間 | **24時間365日 → いつ見ても動いている** | 平日 9:00〜15:30 のみ。夜・週末は静止画になる |
| リアルタイムデータ | 取引所の公開 WebSocket で**無料・口座不要・即日入手** | リアルタイム板は証券口座+API 審査が必要 |
| ペーパートレード開始 | **口座なしで今日から可能** | データ取得の時点で口座開設が必要 |
| 実弾移行 | 国内交換業者 API(bitFlyer / GMOコイン等)で少額から | kabuステーション API 等(審査あり) |
| 判断サイクルとの相性 | ボラティリティが高く、分単位の判断でも画面が動く | 日次サイクル向き。「眺める」体験は単調になりがち |

**推奨**: Phase 1〜2 は仮想通貨(BTC/ETH 中心)。「眺めて面白い」という本プロダクトの目的に対して市場時間・データ入手性・開始スピードのすべてで優位。株式は将来のマルチアセット対応(F-14)として拡張余地を残す。

## 3. システム構成

```
[取引所 公開 WebSocket]──リアルタイム価格──┐
[イベントフィード]──要人発言・経済指標・ニュース─┤
                                            ▼
┌─ エージェント・コア(常駐プロセス)───────────────────┐
│ ① マーケット状態の集約(価格・出来高・テクニカル指標)      │
│ ② LLM 判断サイクル(1〜5分毎): Claude が売買/見送りを判断し │
│    「判断根拠」を日本語で出力 ← ダッシュボードの主役コンテンツ │
│ ③ リスクゲート(コード強制): 上限・損失・頻度チェック        │
│ ④ 執行: Phase 1 = ペーパーブローカー(仮想約定)             │
│         Phase 2 = 取引所 API(少額実弾)                     │
│ ⑤ 記録: 全判断・全取引・損益を DB へ                        │
└──────────────┬───────────────────┘
                              ▼ WebSocket push(1秒以内)
┌─ ダッシュボード(Web アプリ)─────────────────────┐
│ KPI ヘッダ / 価格チャート+売買マーカー / 資産曲線            │
│ エージェント思考ログ / ポジション / 取引フィード / 緊急停止    │
└──────────────────────────────────┘
```

**設計上の決定事項**
- Polymarket 型(31回/時)と違い高頻度ではないため、**LLM を判断ループに入れる**(1〜5 分サイクル)。「Claude がいま何を考えているか」が画面に流れることが本プロダクトの見どころであり、これは意図した設計
- ただしリスク制約(1取引上限・日次損失上限・取引頻度上限)は従来どおり**コードで強制**し、LLM の出力より優先する
- ペーパーブローカーと実弾ブローカーは同一インターフェースで実装し、切替は設定 1 箇所(ダッシュボードに PAPER / LIVE バッジを常時表示)

## 4. 機能要件

### エージェント側
| # | 機能 | 内容 | 優先度 |
|---|------|------|--------|
| F-1 | 価格フィード | BTC/ETH 等の価格・出来高を公開 WebSocket で取得 | 必須 |
| F-2 | LLM 判断サイクル | 市場状態+ポジション+直近成績を Claude に渡し、売買/見送りと**日本語の判断根拠**を取得 | 必須 |
| F-3 | リスクゲート | 1取引上限・日次損失上限・総エクスポージャ上限・取引頻度をコードで強制。違反時は発注拒否+画面表示。保有ポジションの損切り/利確ラインは LLM の判断サイクルとは独立にコード側で常時監視 | 必須 |
| F-4 | ペーパーブローカー | 実勢価格+想定スリッページで仮想約定。残高・ポジション・損益を管理 | 必須 |
| F-5 | 実弾執行 | 国内取引所 API 経由の発注・約定管理(Phase 2) | Phase 2 |
| F-6 | 記録 | 全判断(見送り含む)・全取引・損益推移を DB 保存 | 必須 |
| F-7 | 通知 | 取引・エラー・ガードレール発動に加え、プロセス死活・価格フィード断を即時通知(Slack/LINE)。無人 24/365 稼働(N-2)の前提条件 | 必須 |

### ダッシュボード側
| # | 機能 | 内容 | 優先度 |
|---|------|------|--------|
| F-8 | KPI ヘッダ | 総資産・累計損益・勝率・取引数・稼働時間を一目で | 必須 |
| F-9 | 価格チャート | ローソク足+エージェントの売買マーカー(どこで買い/売りしたか)。タイムフレーム切替: 5分/1時間/4時間/日足/週足/月足。X軸は時刻ラベル+基準線 24 本(表示幅 24 本足: 月足なら 2 年分)。インジケーター: 移動平均線 3 本(MA7/25/99)をチャートに重畳、RSI(14)・MACD(12,26,9) をサブパネル表示(将来: ボリンジャーバンド・出来高等を追加可能な構造) | 必須 |
| F-10 | 資産曲線 | 資産推移(エクイティカーブ)のリアルタイム描画 | 必須 |
| F-11 | 思考ログ | エージェントの判断根拠を時系列カードで表示(**主役機能**) | 必須 |
| F-12 | ポジション/フィード | 保有ポジション一覧と約定フィードのライブ表示 | 必須 |
| F-13 | 緊急停止 | 停止状態はエージェント・コア側で保持: 未約定注文の取消+新規エントリー停止、損切り監視は継続、ダッシュボード切断後も停止状態を維持。画面のキルスイッチと通知からの操作はその入口。PAPER/LIVE バッジ常時表示 | 必須 |
| F-14 | マルチアセット | 監視銘柄の追加(将来: 株式タブ) | 将来 |
| F-15 | イベント収集 | 要人発言(米大統領・FRB 議長等)・経済指標・重要ニュースのヘッドラインをフィード経由で受信し、インパクト(高/中/低)を分類 | Phase 1.5 |
| F-16 | イベントドリブン判断 | 高インパクトのイベント検知時、定期サイクルを待たずに LLM 判断を即時起動。**デフォルト動作は防御(新規エントリー一時停止・ポジション縮小の検討)**。イベント単独では発注せず、価格反応と併せて判断 | Phase 1.5 |
| F-17 | イベント表示 | 検知イベントをダッシュボードにライブ表示し、それに対するエージェントの反応(思考ログ)と紐づけて見せる | Phase 1.5 |
| F-18 | 関連指標(クロスアセット) | 恐怖指数(VIX)・Crypto Fear & Greed・ゴールド・S&P500・ドル指数(DXY)・米10年金利をダッシュボードに常時表示し、**LLM 判断のインプットにも渡す**(例: ゴールド売られ+株先物堅調 → リスクオン資金フローと解釈)。データ源: Fear & Greed は alternative.me(無料)、VIX/ゴールド等は無料ソース(15〜20分遅延)で開始し、必要になれば有料リアルタイムに格上げ | Phase 1.5 |

## 5. 非機能要件

| # | 項目 | 要件 |
|---|------|------|
| N-1 | 更新レイテンシ | 価格・約定・思考ログの画面反映 1 秒以内(WebSocket push) |
| N-2 | 稼働 | 24/365 常駐。プロセス監視・自動再起動。障害時は新規発注停止に倒す |
| N-3 | コスト | LLM 呼び出しは判断サイクル毎のため月額が読める(例: 5分毎 ≒ 月 8,640 回)。月次上限とアラートを設定 |
| N-4 | セキュリティ | Anthropic・取引所の API キーはいずれもシークレット管理で保管し、コード・リポジトリに含めない。取引所キーは出金権限なし。ダッシュボードは認証必須(本人のみ) |
| N-5 | 監査性 | 全判断・全取引が時系列で追跡可能 |

## 6. デザイン要件(ダッシュボード)

参照画像の「クオンツ端末」の情報密度・ワクワク感は残しつつ、次の方針で「見やすく・オシャレ」に:

- **ダークテーマの取引端末**をベースに、参照画像のような CRT 風の過密表示は避け、余白と情報階層を明確に
- 数値はタブラー(等幅)数字で桁を揃え、上昇=グリーン/下落=レッドの意味色は常に一貫
- 主役は「エージェントの思考ログ」: 判断根拠が日本語で流れ、売買はチャート上のマーカーと連動
- KPI → チャート → 詳細(ポジション・フィード)の視線順に配置。装飾よりも一目で状態が分かること
- ※デザインモックアップ(動くプロトタイプ)を `docs/dashboard-mockup.html` として添付。これを叩き台にトーンを確定する

## 7. イベント連携(要人発言・経済指標)の設計方針

### 狙うこと・狙わないこと
- **狙わない**: ヘッドライン発表から数ミリ秒〜数百ミリ秒の速度勝負(プロの HFT ボットの土俵であり、LLM 判断の所要時間では構造的に勝てない)
- **狙う**: ①**防御** — 高インパクトイベント検知時に数秒〜数十秒で新規エントリー停止・縮小(損失回避は速度勝負に勝たなくても価値がある)、②**数分〜数時間の方向性判断** — 発言内容の解釈を Claude が行い、その後の判断サイクルのバイアスに反映

### データソース候補と概算コスト
| ソース | 内容 | レイテンシ | 月額目安 |
|--------|------|-----------|---------|
| 経済指標カレンダー(無料 API/RSS) | CPI・FOMC・雇用統計等の**予定**と結果 | 発表後数秒〜 | ¥0 |
| 暗号資産系ニュースアグリゲータ(Tree of Alpha / Phoenix News 等) | 通信社ヘッドライン+**要人の X ポストを既に集約**(ミリ秒〜秒) | 秒未満 | ¥0〜2万円程度 |
| X API(従量課金) | 特定アカウントの直接ポーリング | ポーリング間隔次第 | 読み取り $0.005/件。**リアルタイム stream は Enterprise(約 $42,000/月)限定のため対象外**。少数アカウントの補完用途のみ |
| 一般ニュース API(GNews 等) | 背景ニュース | 分単位 | ¥0〜数千円 |

**推奨**: アグリゲータ+経済指標カレンダーで開始(月 2 万円以下)。X API 直接契約は行わない(要人ポストはアグリゲータが秒未満で中継するため二重投資になる)。

### 安全設計(誤報対策)
- イベント単独では発注しない(F-16)。フェイクヘッドライン・なりすまし・誤報があるため、**価格の実反応と併せて**判断する
- ソースごとに信頼度を持ち、単一の低信頼ソースのみの場合は「警戒モード(新規停止)」までに制限
- 経済指標は「予定」が事前に分かるため、発表前後は自動的に新規エントリーを止める(カレンダー連動)

## 8. 必要な準備

1. Anthropic API キー(判断サイクル用。月額上限設定)
2. 実行環境: 常駐サーバ(VPS 等)+ ダッシュボードのホスティング
3. 価格データ: 取引所公開 WebSocket(無料。Phase 1 はこれのみで開始可能)
   - Phase 1.5: イベントソースの選定・契約(§7。経済指標カレンダー無料+ニュースアグリゲータ月 2 万円以下を推奨)
4. Phase 2 のみ: 国内暗号資産交換業者の口座+API キー(出金権限なし)、投入資金額と損失許容上限の決定
5. 通知先(Slack/LINE)
6. 税務(Phase 2 以降): 暗号資産の損益は雑所得。損益集計は F-6 の記録から自動生成
7. 運用体制: 週次で人間が判断ログ・成績をレビューする運用ルール、緊急停止手順の確認(取引所側での API キー無効化を含む)

| Phase | 内容 | 完了条件 | 期間目安 |
|-------|------|----------|----------|

| 1.5 | イベント連携(F-15〜F-17): 要人発言・経済指標のフィード接続とイベントドリブン判断 | 高インパクトイベントで防御動作(新規停止)が発火し、思考ログに反応が紐づくことを確認 | 1〜2 週間 |

## 10. リスク・免責事項

- LLM の判断は誤る。ペーパートレードでの成績が実弾で再現される保証はない
- 実弾移行時の元本割れリスクは発注者が負う。本システムは利益を保証しない
- ダッシュボードの見た目の良さと運用成績は無関係である(参照ポストのような成績を約束しない)
